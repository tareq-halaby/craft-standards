AccessKit Node Tagging and Automated CI Accessibility Audit

# STD-A11Y-001: AccessKit Node Tagging and Automated CI Accessibility Audit

## 1. Abstract
Assistive technologies (screen readers, speech input, screen magnifiers) rely on accessibility trees generated by AccessKit. Custom widgets in egui that are allocated via `ui.interact` or `allocate_exact_size` produce empty, unnamed nodes unless explicitly annotated. This standard specifies mandatory accessibility tagging and automated CI testing.

# Storytold Craft Creative Suite Contributor & Agent Guidelines
- Monorepo Architectural Ground Truth: https://tareq-halaby.github.io/craft-standards/
- Invariant Testing: All new UI features MUST comply with the 28 Craft Standards.
- Crate Boundaries: Respect 'The Keep Rule' (STD-LIB-005). Never write app-specific code in core crates.
- ToolSlot Ergonomics: Multi-tool buttons MUST shield against rapid double-clicks (STD-INPUT-001).
- Filesystem: App code must NEVER access `std::fs` directly; route through `craft-fs` sandboxing (STD-SHELL-003).
- Accessibility: Every widget MUST register AccessKit nodes with explicit role, label, and AAA contrast (STD-A11Y-001).
- BiDi / RTL: Full shell direction mirroring is mandatory. Never hardcode Left/Right padding (STD-I18N-001).

# Cursor Rules for ArtCraft Rust Suite
You are an expert Rust graphics & desktop engineer working on the ArtCraft 20+ app monorepo.
Always adhere strictly to the 28 Craft Standards (https://tareq-halaby.github.io/craft-standards/):
1. UI framework is egui with wgpu backend. Use `craft-widgets` design tokens.
2. Ensure AccessKit accessibility trees are built for all custom widgets.
3. Use `cosmic-text` and `craft-text` for BiDi RTL galley shaping.
4. Normalize key chords using `craft-keymap` (Cmd on macOS, Ctrl on Win/Linux).
5. Never bypass confined sandboxing. Use `craft-fs`.
