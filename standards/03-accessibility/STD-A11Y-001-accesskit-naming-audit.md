# STD-A11Y-001: AccessKit Node Tagging and Automated CI Accessibility Audit

## 1. Abstract
Assistive technologies (screen readers, speech input, screen magnifiers) rely on accessibility trees generated by AccessKit. Custom widgets in egui that are allocated via `ui.interact` or `allocate_exact_size` produce empty, unnamed nodes unless explicitly annotated. This standard specifies mandatory accessibility tagging and automated CI testing.

---

## 2. Normative Requirements

### 2.1 Mandatory Roles & Labels
* Every interactive control (buttons, tool slots, sliders, drag values, color pickers, tabs) must possess:
  1. An explicit **AccessKit Role** (`Role::Button`, `Role::Slider`, `Role::Tab`, `Role::TreeItem`).
  2. A localized **Accessible Label** (translated via `craft-i18n`, never hard-coded English).
  3. Bounding box coordinates matching the visual geometry of the control.
* Non-current rows in lists must retain bounds and actions even if unfocusable, so screen readers can point and click.

### 2.2 Canonical Helper API (`craft-ui::a11y`)
Applications must use standard a11y helper functions:
```rust
use craft_ui::a11y;

let resp = ui.allocate_exact_size(size, Sense::click());
a11y::role_name(&resp, egui::accesskit::Role::Button, tl!("Select Tool"));
```

### 2.3 Automated Accessibility Audit in CI
Every ArtCraft application must implement an automated integration test (`tests/it/ui_accessibility_audit.rs`):
* The test launches the main application shell and traverses the entire AccessKit node tree.
* **Failure Condition:** The test must fail if any node with a clickable or focusable action lacks an accessible label (`label.is_empty()`) or has an unknown role.
